### 1.2 Выбор метода интеграции

В качеста метода интеграции был выбран **Run time**.<br>
Идея здесь заключается в том, чтобы создать группу взаимосвязанных веб-приложений, которые могут быть запущены на разных серверах, и могут обмениваться данными друг с другом через хостовое приложение.<br> 
Хостовое приложение будет объединять все эти приложения во время сборки и предоставлять пользователю единый интерфейс для работы со всеми функциями.

### 1.3 Выбор инструмента для создания микрофронтендов

| Критерий | Module-Federation | Single-SPA |
| - | - | - |
| Стек технологий | **+** <br>Единый стек, все готовые модули написаны на React.js</br> | **-** <br>Поддержка модулей написанных на разных фрейворках не требуется</br> |
| Скорость реализации | **+** <br>Небольшой плагин для сборки</br> | **-** <br>По сути сам является фреймворком, на изучение которого нужно время</br> |
| Поддержка | **+** <br>Проще поддерживать</br> | **-** <br>Есть проблемы совместимости с другими фреймворками</br> |
| Итог | **3** | **0** |

**Вывод**: на основании критериев отбора, плагин **Module-Federation** выбран для организации подхода к реализации микрофронтенд архитектруры
